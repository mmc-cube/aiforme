# 双AI协同：构建智能代码优化工作流

通过Claude和Gemini的协同工作，实现代码AI率的自动化降低，并提出优化建议，提升代码的原创性与业务贴合度。

## 引言：双AI协同的代码优化新范式

在AI辅助编程的时代，单一的AI工具往往难以满足复杂的代码优化需求。通过Claude Code和Gemini-CLI的协同工作，我们可以构建一个智能化的代码优化工作流，实现代码质量的自动化提升。这种方法不仅能够有效降低代码的AI特征，还能显著提升代码的业务贴合度和原创性。

基于前面两篇文章的介绍，我们已经了解了Claude Code作为强大的终端AI编程助手，以及Gemini-CLI作为灵活的命令行AI工具。现在，我们将探索如何将这两个工具有机结合起来，形成一个高效的代码优化生态系统。

## 第一步：基础环境搭建

### 1.1 工具安装与配置

首先需要确保两个核心工具都已正确安装并配置：

**Claude Code环境**（参考《Claude Code 完整开发指南》）：
- Node.js v18+ 和npm
- Claude Code CLI安装
- API密钥配置（如需要）
- 项目初始化和CLAUDE.md配置

**Gemini-CLI环境**（参考《Gemini-CLI 终极使用教程》）：
- Node.js环境（可与Claude Code共享）
- Gemini-CLI全局安装
- Google账号认证
- 自定义命令配置

### 1.2 非互动模式设置

关键要点：使用非互动指令避免Gemini直接修改代码，确保工作流的可控性。

```bash
# Gemini CLI非互动模式示例
gemini -p "Explain the architecture of this codebase" < source_file.js
```

这种方式可以确保Gemini只提供分析和建议，而不会直接修改代码，为后续的Claude处理保留控制权。

## 第二步：定义初始工作流

### 2.1 创建Claude Code输出样式

基于Claude Code的自定义输出样式功能，创建一个专门用于双AI协同的输出样式：

```bash
> /output-style:new AI优化工作流
```

在输出样式提示词中，实现以下核心逻辑：
- Claude Code根据用户需求修改代码
- 调用Gemini CLI对代码AI程度进行评估
- Gemini提供具体优化建议
- Claude Code根据建议进一步优化代码

### 2.2 工作流激活与应用

```bash
> /output-style AI优化工作流
```

选择刚刚创建的输出样式后，发送需要优化的代码，系统就会自动执行双AI协同优化流程。

## 第三步：迭代优化提示词

### 3.1 初步效果评估

实际测试中，初次尝试可能遇到效果不佳的问题：
- AI率降低幅度有限（如仅降低5%）
- 大型代码库需要过多迭代次数
- 优化建议不够具体或实用

### 3.2 AI辅助提示词优化

将当前的提示词和遇到的问题提交给其他AI助手，获取专业的改进建议：

```markdown
我想利用claude code修改代码，然后gemini进行评判代码AI率分数，然后给建议到claude code，但是效果并不好，AI率降低不下去，不能强制在修改后让gemini降低。这是我目前的提示词，请给出一些建议。
```

通过这种方式，可以获得更专业的提示词优化建议，提升整体工作流的效果。

## 第四步：专业提示词模板应用

### 4.1 优化的提示词架构

```markdown
# 角色与目标
你现在处于"代码原创性与质量优化模式"。在确保功能正确与可维护性的前提下，
提升代码的业务贴合度与原创性，减少模板化/样板化痕迹，并改进可读性与测试覆盖。

## 严格规范（必须遵守）
- 不许为了"看起来不像模型写的"而添加噪音：禁止无意义TODO、随意变量名、刻意不一致风格、无根据的调试输出。
- 不允许破坏既有对外行为、公共接口与性能SLA；所有变更需最小化风险并保持可回滚。
- 如缺乏业务上下文（领域术语、历史接口、真实边界条件），在本轮仅做保守改进，并产出需要的上下文清单。

## 输入
- 用户需求变更/重构目标
- 现有代码片段/文件
- （可选）领域术语表、历史接口清单、已知边界条件与测试样例

## 工作流
1) **实现变更**：最小化改动达成用户需求，避免引入新依赖与过度设计。
2) **工程化补强**：
   - 提炼与命名：围绕业务词汇重命名关键实体与函数，删除多余层次与死代码。
   - 文档化：只写"必要的、与业务相关"的注释；禁止模板化头注释。
   - 测试：补充/修复单元测试与关键路径用例。
3) **评审请求（给评审模型）**：提交改前/改后差异、测试结果与上下文，索取结构化改进建议。
4) **应用建议**：仅接受"可执行、可验证"的建议；若建议可能破坏行为或缺上下文，改为"请求信息"项。
5) **度量与停止**：
   - 停止条件（满足任一即结束）：  
     a) 重复/克隆率 ≤ 15% 且所有测试通过；  
     b) 评审模型未给出新的"高影响"建议；  
     c) 达到最多迭代N（默认5）或出现质量回退（自动回滚并停止）。
   - 若出现回归或高风险建议，回滚到上一版本并产出风险说明。
```

### 4.2 评审调用机制

```bash
gemini -p "${EVAL_PROMPT}" < path/to/file.ext
```

其中EVAL_PROMPT为结构化的评审提示，要求Gemini返回JSON格式的评估结果，包括：
- originality_score (0-100)
- duplication_ratio (0.0-1.0)
- domain_specificity (0-100)
- maintainability (0-100)
- correctness_risks
- concrete_suggestions

## 第五步：持续优化与完善

### 5.1 优化策略调整

**重新定义目标**：
- 从"把AI评分降到<20"改为"提升原创性与业务贴合度，同时保持功能正确与可维护性"
- 避免以分数为唯一停止条件

**多维客观指标**：

- 重复/克隆率（%）
- 领域术语覆盖率
- 历史依赖/接口真实度
- 测试通过率
- 复杂度变化
- 风格一致性偏差

### 5.2 评审职责专业化

要求评审模型：
- 回避作者来源推断
- 专注代码质量与原创性评估
- 关注业务真实度
- 识别潜在风险与改进点

### 5.3 禁止低质量优化

明确禁止为了降低AI率而采取的低质量手段：
- 无意义TODO添加
- 随意变量命名
- 故意不一致风格
- 调试垃圾代码
- 破坏可维护性的改动

### 5.4 业务上下文融合

在提示词中显式要求：
- 结合项目域名词表
- 考虑历史接口习惯
- 分析真实数据边界
- 既有bug/遗留包袱处理

## 第六步：技术实现细节

### 6.1 结构化输出设计

每次迭代的输出格式：
```markdown
🔄 迭代 #{i}
— 指标：originality={x}/100 | duplication={y}% | domain_fit={z}/100 | maintainability={m}/100 | tests: {passed}/{total}
— 关键建议（最多5条，按影响排序）：
1) [建议描述]
— 已应用变更（摘要diff）：
- [具体变更内容]
```

### 6.2 日志记录系统

在`.claude/opt-log.json`中记录：
```json
{
  "iteration": k,
  "files": {
    "path/to/file": {
      "originality": 78,
      "duplication_ratio": 0.12,
      "domain_specificity": 71,
      "maintainability": 82,
      "review_suggestions": [...],
      "applied_changes": [...],
      "test_summary": {"passed":12,"total":12}
    }
  }
}
```

### 6.3 风险控制机制

- **双阈值与止损**：以"重复率≤15% + 所有测试通过 + 无高风险变更"为停止条件
- **多信号融合**：Gemini结论作为参考，结合静态分析、重复检测、测试与Lint结果
- **自动回滚**：任一迭代引入回归或质量倒退时自动回滚

## 第七步：实际应用场景

### 7.1 代码加工自动化

确定好工作流后，可以自动化简化很多代码的加工流程：
- 批量代码优化
- 遗留系统重构
- 代码风格统一
- 性能优化实施

### 7.2 学术论文降重

同样的逻辑可以应用于：
- 论文降重处理
- AI生成内容优化
- 原创性提升
- 表达方式改进

### 7.3 需求沟通优化

在测试过程中发现，经常需要手动确认才能推进流程。这时需要：
- 明确表达需求
- 分步骤逐步实现
- 充分利用AI的多样化能力
- 通过AI发散思维，实现提效、提速、降本

## 结论：相对性的优化艺术

需要理解的是，AI代码的判定标准是相对的。Gemini对AI代码的判定标准决定了优化的方向。通过调整判定规则，可以实现定向优化。

关键要点：
- MD格式的文档对AI友好，便于处理
- 双AI协同可以显著提升优化效果
- 工作流的持续优化是成功的关键
- 明确的需求表达是AI协作的基础

通过这个双AI协同的工作流，我们不仅能够有效降低代码的AI特征，更重要的是能够提升代码的整体质量和业务价值。这不仅是技术上的创新，更是AI协作模式的探索。
